# SONiC PM Atlas 内容评审意见（2026-09-15）

- 评审对象：http://10.20.30.203:8788/ 全部 12 个页面（首页、3 天入门 ×3、能力线 ×6、术语、核验包、案例）
- 评审方式：新任产品经理视角全站通读（正文逐页提取核对，JS 已确认无隐藏动态内容）
- 站点定位（已与需求方确认）：读者为**新任产品经理 + 售前 + 测试**三类角色；用途为**新人培训**；需支撑**团队成长梯度**

## 一、总体结论

方法论扎实，知识本体偏薄。全站正文合计约 1 万字，平均每条能力线仅 400–1000 字，一小时可通读完毕。作为「上岗第一周方法论手册」够用且质量高；作为支撑「新人培训 + 三类读者 + 成长梯度」的知识站，内容量与深度均不足，「12 周」路线的中间材料大半缺位。

## 二、应保留的优点

1. 「支持」四层责任地图（芯片 / 平台 / 镜像 / 服务），切中「生态声明 ≠ 型号级 HCL」这一最大误区；
2. 工具页实用：参数四态（有值 / 待复核 / 未披露 / 抽取失败）、核验包 10 字段、证据五要素、案例页六层追问，可直接用于会议；
3. 学习闭环完整：每页有检查点、产出清单、周会可用的核对问题。

## 三、按确认后定位的具体缺口

### A. 面向三类读者的分层缺口

现有内容全部按 PM 视角撰写。售前需要「客户常见问题应答口径、竞品对比要点、案例库」；测试需要「用例设计要点、指标基线、测试床搭建指南」——站内均无。
**建议**：同一知识底座上建角色导航（PM / 售前 / 测试三条学习路径），每条能力线标注「按角色读法」与各角色产出。

### B. 新人培训用途的缺口

- 无自测题与通过标准：现检查点为定性描述，培训组织者无法判分；
- 无学习进度跟踪、无练习参考答案；
- 无「第 0 天」入口：环境准备、所需权限账号、遇到问题找谁。
**建议**：每页补 3–5 道自测题（答案可折叠）；关键页加动手任务的验收标准；首页加培训使用说明（周期、考核方式、结业标准）。

### C. 成长梯度的缺口

站点声称「12 周建立产品判断力」，但实际只有每两周一页的任务卡，知识密度撑不起 12 周节奏。
**建议**：显式定义 L1–L3 能力等级（示例：L1 能核验外部材料 → L2 能主导定型评审 → L3 能定产品路线与生态策略），每级配知识清单、任务与考核证据；现有内容明确标注为 L1。

### D. SONiC 知识本体的缺口（最大短板）

1. **架构线过薄**（正文约 760 字）：仅覆盖 CONFIG_DB → OrchAgent → SAI → syncd 主链一小段。缺：容器全景（orchagent、FRR、teamd、telemetry、snmp、syncd 等各自职责）、APP_DB / STATE_DB / CONFIG_DB 关键表速查、warm-reboot / fast-reboot 机制、「哪些容器重启不影响业务」的重启矩阵。
2. **功能特性地图空白**：L2（VLAN / STP / LAG / MCLAG）、L3 与 BGP（FRR）、EVPN / VXLAN、QoS / ACL、DHCP、SNMP / gNMI 遥测、PortChannel 等均无系统条目。EVPN 只作为「要拆场景」出现。应每项配齐：社区仓库 → 容器 → 关键 DB 表 → 配置入口 → 验证命令。
3. **零真实样例**：无 config_db.json 片段、无 CLI 与 show 命令示例、无测试报告样例；全站无一张内容配图（纯文字 + 表格）。PM 可不亲手配置，但必须能读懂研发给的配置与测试报告。
4. **版本与生态坐标系缺失**：全站反复要求「结论对上版本」，却没有页面讲社区 release 节奏与命名规则、主要商业发行版格局、主流 ASIC（Tomahawk / Trident / Prestera / Spectrum 等）与白牌整机对照。案例页提及的名词均点到为止。
5. **零外部链接**：无 SONiC 官方文档（sonic.readthedocs.io）、GitHub 组织、OCP 社区入口。「社区与上游」能力线不给社区地址，属硬伤。

### E. 站点维护机制问题

- 版本号不一致：首页标 v1.0，内容页标 v1.1；
- 无更新日志（changelog）、无内容负责人、无页面评审日期——与站点自身强调的「基线哈希变化自动失效复核」原则不符；
- 无站内搜索、无完整目录页（sitemap）。

## 四、建议改造清单（按优先级）

**P0 · 培训可用性（先让培训能组织起来）**
1. 统一全站版本号；新增 CHANGELOG 页与「内容 Owner + 最近评审日期」列；
2. 每页补 3–5 道自测题（含可折叠答案）与动手任务验收标准；
3. 首页加三类读者导航（PM / 售前 / 测试）与培训使用说明（周期、考核、结业标准）。

**P1 · 知识底座（补足「可查的货」）**
4. 架构线扩容：容器全景图 + Redis DB 关键表速查 + 容器重启影响矩阵；
5. 新增「功能特性地图」页：功能 × 仓库 × 容器 × DB 表 × 验证命令；
6. 新增「版本与生态坐标系」页：release 节奏、商业发行版对照、ASIC / 白牌矩阵，附官方文档与社区外链；
7. 每条能力线至少补 1 个真实样例（配置片段、测试报告节选、HCL 行示例）。

**P2 · 成长梯度与长期运营**
8. 定义 L1–L3 能力等级与对应考核证据，映射到 12 周路线；
9. 案例页扩容：每类案例补售前应答口径与测试用例要点；
10. 新增 FAQ 页，从各页「核对问题」沉淀；补全站目录页与站内搜索（静态站可用前端全文检索方案）。

## 五、评审边界说明

本评审基于 2026-09-15 抓取的站点快照，仅针对内容规划与知识覆盖，不涉及视觉与代码质量；文中功能与生态条目为方向性建议，具体条目应对照 SONiC 官方文档与公司产品线实际情况核实后落地。
