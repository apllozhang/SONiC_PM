厂商案例拆解（分层练习）

本页以公开叙事为练习材料，训练区分芯片、软件分发、平台适配、硬件、测试加固和支持服务。不是厂商排名，也不是型号支持清单。

案例分层核验

练习框架

每一则公开材料都按六层问：芯片 → 平台 → 镜像 → 硬件/光学 → 测试加固 → 支持服务。问完再决定能不能写进定型表。

案例 A：芯片商 + 整机 ODM

  • 常见叙事：Enterprise SONiC 覆盖 StrataXGS 系列大量 ODM 平台；整机侧在开放交换机上做 harden，强调与多来源光模块协同验证。
  • 分层追问
    • 芯片：目标 ASIC 与 SAI 版本？内核是否锁定？
    • 平台：目标板卡的 ONIE/CPLD/端口映射证据？
    • 加固：每个补丁的 Issue/PR、CI、DUT、已知限制与 Owner？
    • 光学：是否落到你项目的 HCL 行？
  • 易错：把「50+ 平台」当成「我的型号已支持」。

案例 B：AI / 高带宽芯片定位

  • 常见叙事：以 Tomahawk 5 等介绍 51.2 Tb/s 与 AI/ML 数据中心定位。
  • 分层追问：整机是否采用该芯片？镜像与插件是否适配？RoCE 拥塞验证是否拆到封装/隧道/解封装？
  • 易错：芯片公开定位 = 客户 AI Fabric 已验收。

案例 C：开放管理路径（Prestera / OpenLAN 类）

  • 常见叙事：SAI、SONiC、客户端、gNMI/gNOI/REST 与云管 SDK 串成开放管理路径。
  • 分层追问：哪些进目标镜像？权限与证书如何？断网自治？对接客户网管的字段映射？
  • 易错：架构齐全 = 管理面产品化已完成。

案例 D：商业发行（PowerSwitch 类叙事）

  • 常见叙事：社区代码 + 品牌平台 + 镜像版本 + 授权 + ONIE + 升级资料，绑定为可服务交付。
  • 分层追问：仅列出的型号与授权路径是否覆盖你的项目？非列出硬件能否外推？
  • 易错：商业发行文档外推到非清单硬件。

售前应答口径（每类案例）

客户可能问不建议建议口径要补的证据
「你们支持 50+ 平台，我这型号肯定行吧？」 「对，生态都支持」 「生态范围很广；具体到贵司型号与光模块，我们按 HCL 与镜像版本核对后书面确认。」 目标 HW-SKU + 镜像版本 + 实验室互通行
「芯片手册写了 EVPN，方案里就能写支持吧？」 「可以写支持 EVPN」 「芯片能力是前提；我们按贵司拓扑（L2/L3 路径）给出已验证范围与未验证项。」 路径级验收记录与报告编号
「社区已经有这功能，商业版一定有吧？」 「社区有就一定有」 「商业发行以我们清单与版本为准；社区有不等于已纳入支持与补丁流程。」 发行版功能清单与补丁窗口条款
「竞品宣传 harden，你们有吗？」 「我们也 hardened」 「我们可以说明补丁选取、CI 与平台验证流程，并给出可追溯清单范围。」 补丁追溯链样例（脱敏）

原则：不否定客户场景，不把未验证项说成已验证；把对话拉回型号、版本与证据。

测试用例要点（每类案例）

案例类型测试应覆盖证据形态
芯片 + ODM 平台 目标 SKU 冷启动、端口映射、光学互通、温升与双电源 实验室记录 + HCL 行 + 版本号
AI / RoCE 类 PFC/ECN 阈值、拥塞点、封装/隧道/解封装路径、恢复时间 流量仪报告 + 交换机计数器 + 配置片段
开放管理 / 遥测 订阅时延、丢点率、证书与权限、断网行为 抓包或服务端日志 + 断网演练
商业发行交付 安装/升级/回退、诊断包收集、授权与 entitlement 校验 升级回退记录 + Support Bundle 样例
边界：本页只用于内部训练分层阅读能力。对外材料请以各厂商最新官方文档与你的合同范围为准。

动手任务验收标准

  • 完成至少 1 则案例的六层追问笔记
  • 填写练习模板 3 行（材料/层/原句/改写/证据）

自测题（点击展开答案）

自测 1：六层追问是哪六层？
芯片/SAI、平台/板卡、镜像/补丁、硬件/光学、测试/加固、支持/生命周期。
自测 2：案例页能否当厂商排名或支持清单？
不能。仅用于分层阅读训练；对外以官方文档与合同为准。
自测 3：「50+ 平台」在练习里应改写成什么？
目标型号 × 端口分拆 × 光模块 × 镜像版本是否在本项目 HCL 上。

建议：正确率 ≥ 80% 再进入下一页。培训组织者可按此判分。
